02

Built for thumbs first

Touch is the primary input here, not a port of a keyboard game.

A swipe that scrolls the page mid-run is a bug, and so is a long-press callout appearing while you drag a paddle. The fixes are unglamorous and they are the difference between a game that works on a phone and one that merely loads on it.

  • Gesture ownership — touch-action: none on the board stops a swipe from scrolling, and overscroll-behavior: none kills pull-to-refresh mid-game.
  • Per-game controls: an on-screen d-pad for Snake, swipe for Snake and 2048, drag for Breakout and Pong, long-press or flag mode for Minesweeper.
  • Real fullscreen where it exists, a full-viewport layout where it does not — the ⛶ button or F uses the Fullscreen API, and falls back to a viewport layout on iPhone, where element fullscreen is unsupported. Esc or the floating ✕ exits.
  • Nothing is selectable on a play surface: text selection, long-press callouts and the context menu are all disabled.
03

Nothing to build

Static files served straight from the repository root, with one shared toolkit behind all eight games.

Every game is its own page plus one script. common.js supplies what they all need: score storage that knows whether higher or lower is better, a tiny synthesised sound kit, canvas fitting, directional-key and swipe helpers, and overlay show/hide. Personal bests stay in localStorage, on the device you play on, with no account and no server.

python3 -m http.server 3000
# then open http://localhost:3000

Adding a game is three steps: copy a page, write a script against the PP helpers, and add a card to the hub with an accent colour and a record badge.
