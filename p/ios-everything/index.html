01

What it is meant to hold

The premise is that iOS is missing a single, sensible collection of the small tools people actually need.

The repository describes itself plainly: a GitHub repository with many of the tools needed for iOS, including .ipa files, an app repository, bookmarklets, and much more. The intended shape is a one-stop repo for sideloading utilities — the apps, the sources they install from, and the small bookmarklet tricks that make a phone easier to live with.

  • .ipa files — the packaged apps themselves, ready to sideload.
  • An app repository — a source other tools (like SEUsign) can point at.
  • Bookmarklets — the one-line scripts that do something the browser will not.
02

Status, without spin

It is early, and the README says so rather than padding the page.

Right now the repository is the README and the plan. There is no app bundle, no source list and no bookmarklet folder yet — the project is a place being prepared, with packaging help credited to ByePassHub, and a promise to keep adding to it.

Watching the repo is the useful action today: it is the notification for the first real drop, and the issues tab is the place to say what should go in first.

03

Why it is here at all

A project page can be honest about being unfinished — that is what the "in progress" badge on the home page is for.

Everything on this site is public, including the things that are not done. Listing iOSeverything alongside the finished work is a record of what is planned, and the reason the site has a category filter that can show just the iOS work.

Released under CC0-1.0, so whatever ends up in it can be reused without asking.
