Raw File Website

Upload a file, get a raw link you can copy, share, hotlink or embed — from static hosting that cannot run an upload server. Uploads are committed into your own repo instead.

01

Why uploads go through the API

Pages can serve files. It cannot accept them. The GitHub API can do both.

You fill in owner, repo and branch, paste a fine-grained token with Contents: read and write, and drop files. They are committed to uploads/ in your repository, and each one comes back with working links: a raw.githubusercontent.com URL and the equivalent Pages URL. The token stays in your browser.

  • Every link is raw bytes. No preview pages, no interstitial, nothing to click through — the URL is the file.
  • Delete means delete: removing an entry takes out its pieces, manifest, published release asset and index row, so its raw link stops working.
  • No Git LFS, deliberately: its upload server blocks browsers, its free quota is small, and LFS-tracked files serve as pointer text on raw links, which would break the whole premise.
02

Big files are split, then reassembled

GitHub caps a single file at 100 MB and the API rejects big blobs, so size is handled by chopping the file rather than by refusing it.

Up to roughly 40 MB a file uploads as one blob with a direct raw link. Past that, it becomes 10 MB pieces plus a small manifest, and still shows up on the page as a single entry. An Actions workflow then reassembles the pieces and publishes the result as a release asset, which serves the true bytes at a stable URL.

  • Files from roughly 40 MB to 2 GB go this route, and the entry gains its release-asset raw link a few minutes after upload.
  • Links are tracked in uploads/files-index.json, so the page can list what exists without walking the tree.
  • If GitHub refuses a single big blob anyway, the site splits it automatically and says so instead of failing silently.
03

One queue, resumable

Parallel uploads into one branch is how you get 409s. So there is a single save queue.

Every save goes through one queue with automatic retry, which stops two simultaneous uploads from tripping over the branch head. If a long upload stalls, it pauses with ↻ Resume, continuing from the pieces already saved, and Discard — rather than dying and losing the work.

Deleting a multi-piece entry clears its manifest and every piece, so nothing is left behind to be reassembled later.

04

Self-host for no limits

The same page detects a server and switches modes, so you get unlimited size without a second app.

The bundled zero-dependency Node server streams raw bytes straight to disk — no size limit and no buffering the file in memory — and serves raw links with the right content type and Range support.

node server.js
# open http://localhost:3000

POST   /api/upload?filename=…
GET    /api/files
DELETE /api/files/:id
GET    /api/health
